Turn search infrastructure into a usable product surface

MySearch unifies Tavily, Exa, Firecrawl, and Social / X into one search entry that Codex, Claude Code, and team agents can call directly. Users do not need to maintain multiple providers, compatible gateways, or result formats, and they do not need to decide manually whether a task should use web search, content extraction, or social sentiment.

Unified Entry Web discovery, content extraction, and social sentiment all share the same integration path.
Exa Workspace Give Exa its own workspace with independent key management, token issuance, and direct proxy access.
Unified Operations Keep key pools, token pools, quota sync, and team-facing access in one console.
Unified Compatibility Support both official APIs and custom compatible gateways without locking into a single backend.
Router Tavily for Discovery

Best for news, fast answers, and early web discovery. It sits in the first routing layer of MySearch.

Search Exa for Web Discovery

Best as a complementary web-discovery path beyond Tavily, with its own key pool, token pool, and proxy endpoint.

Depth Firecrawl for Extraction

Docs sites, GitHub, PDFs, pricing pages, and changelogs are usually more reliable through Firecrawl.

Social Social / X for Sentiment

Works with grok2api and xAI-compatible search backends, then normalizes X results into a structure MySearch can consume directly.

Powered by grok2api The Social / X workspace currently defaults to grok2api

This capability is wired through grok2api-compatible interfaces plus the upstream token state it exposes. MySearch credits the grok2api project here and keeps it as the default compatible implementation source.
